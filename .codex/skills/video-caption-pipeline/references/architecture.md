# Video Caption Pipeline Architecture

## 1. Product Boundary And Terminology

The Video tab needs three distinct text concepts:

| Product label | Domain type | Purpose | Timing source |
| --- | --- | --- | --- |
| Phụ đề theo lời nói | `speech` | Show words spoken in the audio | ASR word/segment timestamps |
| Chữ AI theo ngữ cảnh | `context` | Add hooks, facts, benefits, CTA, or explanations supported by content and company knowledge | Scene boundaries plus reading duration |
| Mô tả bài đăng | `post_description` | Text sent beside the video to TikTok/Facebook | No in-video timeline |

`speech` and `context` belong to the video-caption pipeline. `post_description` remains part of marketing/publishing content. The UI and API must not store these in the same field.

The universal entry point should be a Video subtab named **Phụ đề & chữ trong video**. It must work with uploaded videos, media-library videos, and videos generated by Veo, HeyGen, campaign workers, or future providers.

## 2. Current Repository Touchpoints

Inspect these areas before implementation because names and contracts may evolve:

- `src/components/content-studio/ContentStudioWorkspace.tsx`: top-level media tabs and Video subtabs.
- `src/components/content-studio/HeyGenOptionsDrawer.tsx`: existing caption style controls that may be extracted and reused.
- `src/components/content-studio/HeyGenVideoPreview.tsx`: current overlay preview behavior.
- `src/components/content-studio/VideoEditScriptPanel.tsx`: current segment-level caption editing concepts.
- `server/interface/ai-media.interface.ts` and `server/model/ai-media.model.ts`: output metadata only; insufficient as the editable caption domain.
- `server/service/ai-knowledge.service.ts` and `server/model/ai-knowledge.model.ts`: company-scoped knowledge currently shaped around Sale.
- `server/interface/marketing-content.interface.ts`: selected content, body, outline, voice script, campaign and slot links.
- `server/interface/marketing-campaign-slot.interface.ts`: background media workflow and campaign audit state.

Do not overload `AIMedia.metadata.captionedVideoUrl` or `subtitleUrl` with project state. Those fields may remain output pointers, while editable projects, segments, provenance, and jobs live in dedicated collections.

## 3. Target Flow

```text
video source
  -> media validation and fingerprint
  -> metadata/audio/scene analysis
  -> speech transcription and/or context collection
  -> caption candidates
  -> hard validation and scoring
  -> editable timeline draft
  -> user or campaign approval gate
  -> final render worker
  -> verified output asset
```

Analysis and draft generation must be separable from final rendering. Users should receive transcript/scene progress and an editable low-cost preview without waiting for a full-resolution render.

## 4. Domain Model

### 4.1 VideoCaptionProject

Create a tenant-scoped project instead of embedding the workflow in a React component:

```ts
type CaptionMode = "speech" | "context" | "combined";

interface VideoCaptionProject {
  companyCode: string;
  createdBy: ObjectId;
  name: string;
  mode: CaptionMode;

  source: {
    kind: "upload" | "media_library" | "generated" | "campaign";
    mediaId?: ObjectId;
    url: string;
    fingerprint: string;
  };

  video: {
    durationMs: number;
    width: number;
    height: number;
    fps?: number;
    hasAudio: boolean;
    language?: string;
    proxyUrl?: string;
  };

  contextLinks?: {
    marketingContentId?: ObjectId;
    campaignId?: ObjectId;
    campaignSlotId?: ObjectId;
  };

  knowledgeSnapshot?: {
    purpose: "caption";
    sourceIds: ObjectId[];
    indexVersion?: string;
    retrievedAt?: Date;
  };

  style: CaptionStyle;
  status: CaptionProjectStatus;
  currentVersion: number;
  progress?: { stage: string; percent: number; message?: string };
  output?: {
    subtitleUrl?: string;
    captionedVideoUrl?: string;
    previewUrl?: string;
    renderHash?: string;
  };
  lastError?: ClassifiedError;
  createdAt: Date;
  updatedAt: Date;
}
```

Suggested statuses:

`draft`, `queued_analysis`, `analyzing`, `transcribing`, `generating_context`, `ready_for_review`, `queued_render`, `rendering`, `completed`, `retrying`, `failed`, `cancelled`.

Keep project status transitions explicit and auditable. A status must reflect completed artifacts, not only a provider request being accepted.

### 4.2 VideoCaptionSegment

Store segments independently or as bounded versioned project children. Do not lose prior user edits when regenerating.

```ts
interface VideoCaptionSegment {
  companyCode: string;
  projectId: ObjectId;
  version: number;
  lane: "speech" | "context";
  startMs: number;
  endMs: number;
  text: string;
  sceneId?: string;
  confidence?: number;
  sourceReferences: CaptionSourceReference[];
  styleOverride?: Partial<CaptionStyle>;
  lockedByUser?: boolean;
  sortOrder: number;
}
```

Source references should identify the exact supporting object when possible:

```ts
interface CaptionSourceReference {
  kind:
    | "user_input"
    | "marketing_content"
    | "campaign_slot"
    | "knowledge_chunk"
    | "video_scene"
    | "speech";
  sourceId?: string;
  documentId?: string;
  chunkId?: string;
  title?: string;
  version?: string;
  excerpt?: string;
}
```

Do not expose confidential full chunks to the browser. Return only the short evidence excerpt the user is allowed to see.

### 4.3 Jobs And Audit

Use queue jobs or a dedicated `VideoCaptionJob`/transition log for:

- stage, attempt, provider, model, and operation;
- lease ID, lock time, and expiry;
- idempotency key and input hash;
- token/media duration usage and cost;
- provider request/result IDs;
- retry classification and sanitized errors;
- started/completed timestamps.

Recommended idempotency basis:

`companyCode:projectId:videoFingerprint:mode:inputVersion:settingsHash:operation`

## 5. Shared Company Knowledge

### 5.1 Move The Domain, Preserve Consumers

Move the company-document UI and generic service boundary outside Sale into a shared **Kho tri thức doanh nghiệp** domain. Sale remains one consumer; caption generation becomes another. Do not break existing sales-reply behavior during the move.

The knowledge record should support:

- `companyCode`, owner, access role/team, source, status, version, and timestamps;
- purpose scopes such as `sales`, `support`, `marketing`, `caption`, and `all`;
- platform scopes including `facebook`, `zalo`, `tiktok`, and `all`;
- source types such as manual text, Google Docs/Drive, uploaded files, web pages, products, and policies;
- sync state, content hash, index version, deletion/tombstone state, and failure reason;
- document/chunk provenance returned by retrieval.

The current knowledge schema and search behavior must agree on channel values. In particular, a TikTok/caption query must not silently retrieve only documents marked `all` because the schema cannot store `tiktok`.

### 5.2 Retrieval Policy

Build a generic retrieval service with purpose-specific adapters. Caption generation should not reuse a sales-response prompt or sales-only query heuristic.

Context priority:

1. User-entered instructions and facts for this project.
2. Linked selected `MarketingContent` and its campaign/slot brief.
3. Verified company knowledge retrieved with `purpose=caption`.
4. Observations inferred from video/audio.

Load linked marketing content and campaign objects directly by tenant-scoped IDs. Do not insert every campaign post into the vector store merely to caption one video.

Retrieval output must include document and chunk provenance, score, version, and a bounded excerpt. Apply a context budget per scene and globally so long documents cannot crowd out direct campaign context.

### 5.3 Security

- Enforce company and permission filters before retrieval, not after.
- Use short-lived signed URLs for private source files and media.
- Validate remote protocols/domains and defend against SSRF.
- Validate MIME type, size, and duration; scan uploads when supported.
- Sanitize provider errors and never log secrets or entire private documents.
- Define retention and deletion behavior for original media, proxies, transcripts, chunks, and final renders.

## 6. Speech-To-Text Pipeline

1. Validate and fingerprint the source video.
2. Probe duration, dimensions, frame rate, and audio streams.
3. If no usable speech exists, finish with an explicit `no_speech_detected` result rather than retrying indefinitely.
4. Extract normalized audio for the transcription provider.
5. Detect or accept language and request word-level timestamps where supported.
6. Normalize punctuation and timestamps without inventing spoken content.
7. Segment at phrase/sentence boundaries using readability rules.
8. Produce editable segments and optional SRT/VTT files.
9. Render only after review or an explicit campaign policy allows automatic rendering.

Initial readability defaults should be configurable rather than hard-coded:

- one or two lines;
- target 32-42 characters per line;
- target 15-20 characters per second, calibrated for Vietnamese;
- minimum visible duration around 700 ms;
- maximum segment duration around 6 seconds;
- no negative duration or accidental overlaps in the same lane.

Preserve original ASR confidence and word timing so later re-segmentation does not require retranscription.

## 7. Contextual Caption Pipeline

Contextual captions are evidence-grounded on-video overlays, not a transcript.

### 7.1 Analyze Video Structure

Create a reusable analysis artifact containing:

- shot/scene boundaries and representative frames;
- OCR text and important on-screen regions;
- detected subjects/actions/products when confidence is sufficient;
- motion and composition safe areas;
- audio presence and relevant transcript summary;
- uncertainty markers.

Do not infer company-specific prices, guarantees, features, or claims from pixels alone.

### 7.2 Build Scene Context

For the whole video and each useful scene:

- load explicit user instructions;
- load linked winning marketing content, slot objective, CTA, outline, and voice script;
- query company knowledge with scene-aware search terms;
- attach supporting references and their versions;
- keep visual observations separate from business facts.

### 7.3 Generate, Validate, And Select

Generate a small bounded set of materially different candidates for each selected scene. Then apply hard validation before scoring:

- every business claim has an allowed direct or knowledge source;
- text fits line, duration, and reading-speed limits;
- timing stays inside valid scene/video bounds;
- captions do not repeat adjacent segments or conflict with visible speech text;
- unsafe, prohibited, placeholder, or unsupported language is rejected;
- CTA frequency and brand terminology respect project/campaign rules;
- important faces, products, and existing text are not covered.

Score valid candidates for evidence fidelity, scene relevance, campaign objective, readability, visual fit, and novelty. Persist the winning candidate decision and rejection reasons.

Place captions using scene boundaries plus estimated reading duration. Never distribute captions uniformly across the video solely from total duration.

## 8. Combined Mode

Implement combined mode only after both individual modes are stable:

- speech and context use separate timeline lanes;
- default speech placement is bottom safe area;
- default context placement is top or an analysis-selected safe area;
- detect temporal and spatial collisions;
- context yields to essential speech unless the user overrides it;
- editing or disabling one lane must not regenerate the other;
- export/render must preserve deterministic z-order and style.

## 9. API Surface

Use repository conventions and auth middleware. A suggested resource surface is:

- `POST /api/v1/video-caption-projects`
- `GET /api/v1/video-caption-projects`
- `GET /api/v1/video-caption-projects/:id`
- `PATCH /api/v1/video-caption-projects/:id`
- `POST /api/v1/video-caption-projects/:id/analyze`
- `POST /api/v1/video-caption-projects/:id/generate`
- `PUT /api/v1/video-caption-projects/:id/segments`
- `PATCH /api/v1/video-caption-projects/:id/segments/:segmentId`
- `POST /api/v1/video-caption-projects/:id/render`
- `POST /api/v1/video-caption-projects/:id/retry`
- `POST /api/v1/video-caption-projects/:id/cancel`
- `GET /api/v1/video-caption-projects/:id/jobs`

Mutation endpoints should accept an idempotency key or derive one safely. Return project state and progress consistently. Do not make a long-running HTTP request wait for transcription or final video rendering.

## 10. Queue, Rendering, And Performance

Use separate concurrency controls for:

- video analysis/proxy generation;
- transcription;
- contextual AI generation and retrieval;
- preview/final rendering.

Workers must use atomic leases, recover expired jobs, cap retries, and classify validation, authentication, budget, provider, transient, and terminal failures.

Optimize perceived wait time:

1. Create the project immediately and show validated source metadata.
2. Generate/use a low-resolution proxy.
3. Stream or poll named stage progress.
4. Show transcript and analyzed scenes as soon as each becomes available.
5. Build a client preview from the timeline where possible.
6. Run a full-resolution render only after approval.

Cache by stable inputs:

- video fingerprint -> probe, proxy, scenes, OCR, transcript;
- document/index version plus query -> bounded retrieval result;
- project segment version plus style/media hash -> render output.

Never reuse a cache item across companies. A retry must not duplicate charges or final assets. Support cancellation at safe stage boundaries.

Rendering must:

- support Vietnamese fonts and embedded font assets;
- respect portrait, landscape, and square safe areas;
- preserve audio/video sync and source duration;
- handle emoji/font fallback intentionally;
- upload the output before marking the job completed;
- verify output reachability and basic media metadata.

## 11. Video Tab UX

Recommended layout:

1. **Choose video**: upload, media library, or generated/campaign video.
2. **Choose mode**: Speech, Context, or Combined.
3. **Choose context** for contextual mode:
   - linked campaign/post;
   - company knowledge sources;
   - optional user instructions.
4. **Generate draft** with clear stage progress and cancel/retry.
5. **Review timeline**:
   - center video preview;
   - bottom lane timeline;
   - segment list/inspector;
   - source evidence and confidence for context segments;
   - readability/collision warnings.
6. **Style and render**: reusable presets, safe-area controls, preview, final render, and result download/use.

Essential states:

- unsupported/expired video;
- no audio or no speech;
- no accessible company knowledge;
- missing evidence for a claim;
- partial provider result;
- user-edited/locked segment;
- autosaved draft;
- offline/reopen recovery;
- queued, running, retryable failure, terminal failure, cancelled, completed.

Reuse existing HeyGen style controls and segment editor concepts only after extracting provider-neutral components. Do not duplicate style implementations in each video provider.

## 12. Automated Campaign Integration

Campaign creation persists only caption policy, such as:

- required/optional/disabled;
- mode and style preset;
- allowed knowledge scopes;
- automatic review threshold;
- fallback behavior and budget limit.

Actual caption generation occurs just in time after candidate selection and when the slot enters media generation:

```text
winning MarketingContent
  -> video created/selected
  -> caption project created with slot/content links
  -> analysis and caption draft
  -> policy validation or human review
  -> final caption render
  -> media verification
  -> slot ready_to_publish
```

Persist caption project ID, version, output URL, cost, errors, and transitions on the media/slot linkage. A required caption failure prevents readiness and becomes an explicit retryable or `needs_attention` state.

Use the campaign worker lease and publish idempotency rules. TikTok must never publish a missing, incomplete, or unreachable video.

## 13. Rollout Plan And Acceptance Criteria

### Phase 0: Contracts And Product Decisions

Deliver:

- terminology and UX labels;
- project/segment/job schemas;
- state machine and error taxonomy;
- provider adapter interfaces for ASR, video analysis, generation, and rendering;
- source precedence and evidence policy;
- API and queue payload contracts.

Acceptance:

- speech, context, and post description cannot be confused in types or UI;
- every long-running action has a persisted state and terminal outcome;
- no provider name leaks into the core domain contract.

### Phase 1: Caption Core And Video-Tab Shell

Deliver:

- caption models, indexes, permissions, CRUD APIs, and audit transitions;
- Video subtab shell and source chooser;
- project autosave/reopen;
- media validation, fingerprint, probe, proxy, and progress events;
- queue skeleton with leases, idempotency, cancel, and retry.

Acceptance:

- a project survives refresh/browser close;
- company A cannot access company B's projects or media;
- repeated requests do not create duplicate jobs.

### Phase 2: Speech Subtitle MVP

Deliver:

- ASR adapter with timestamps;
- normalization and segmentation;
- timeline editor and style presets;
- SRT/VTT export;
- preview and final burn-in render;
- no-speech and provider-error UX.

Acceptance:

- Vietnamese text and timing remain synchronized on representative videos;
- users can edit and lock segments before rendering;
- retry does not retranscribe an unchanged video unnecessarily;
- completed output is reachable and media-validated.

### Phase 3: Shared Company Knowledge

Deliver:

- shared Knowledge Center UI and generic knowledge service;
- purpose/platform/source scopes including caption and TikTok;
- access control, sync/version/hash/status, provenance, and deletion;
- compatibility adapter for current Sale consumers;
- tenant-scoped caption retrieval API/service.

Acceptance:

- Sale behavior remains compatible;
- caption retrieval returns only permitted company sources with references;
- updating a document creates an identifiable new knowledge version;
- TikTok/caption scope works explicitly rather than falling through to `all`.

### Phase 4: Contextual Caption MVP

Deliver:

- reusable scene/OCR/safe-area analysis;
- direct marketing-content and campaign-slot context loading;
- scene-aware RAG;
- bounded candidate generation, hard validation, scoring, and audit;
- evidence panel, confidence/warnings, and context timeline;
- contextual render.

Acceptance:

- every factual business caption is traceable to an allowed source;
- unsupported claims are rejected or require review;
- timing follows relevant scenes and readability limits;
- final captions do not cover configured important regions.

### Phase 5: Combined Mode And Editing Polish

Deliver:

- two-lane timeline, collision detection, z-order, and independent regeneration;
- segment locking, undo/version restore, keyboard editing, bulk style changes;
- reusable caption components extracted from provider-specific UI;
- responsive, accessibility, and empty/error-state polish.

Acceptance:

- regenerating context preserves locked speech edits and vice versa;
- overlapping captions resolve predictably;
- the same project renders deterministically.

### Phase 6: Campaign Integration

Deliver:

- campaign/slot caption policy;
- just-in-time worker orchestration after winning content and video exist;
- budget/cost tracking, readiness checks, retry/attention states;
- manual review override and audit links from slot to caption project/output.

Acceptance:

- campaign creation generates no final captions;
- browser state is irrelevant to execution;
- retries neither duplicate renders nor publish twice;
- required captions and final video are verified before TikTok readiness.

### Phase 7: Hardening And Rollout

Deliver:

- unit, integration, render golden-frame, queue recovery, security, and E2E suites;
- metrics, structured logs, dashboards, alerts, and provider cost reporting;
- data retention/cleanup jobs and migrations;
- feature flags and staged release;
- provider fallback policy and operational runbook.

Acceptance:

- operators can explain every project's state, source, version, cost, retry, and result;
- expired leases recover safely;
- partial provider failures preserve editable work;
- rollout can be disabled without corrupting existing media or campaign state.

## 14. Test Matrix

Cover at minimum:

- no audio, music only, one speaker, multiple speakers, noisy audio, Vietnamese/English mixed speech;
- portrait, landscape, square, very short, long, variable-frame-rate, and rotated videos;
- empty knowledge, denied knowledge, stale/deleted source, conflicting sources, and updated versions;
- contextual claims with and without evidence;
- timeline edge cases: zero/negative duration, out-of-range time, overlaps, long words, emoji, and two lanes;
- worker crash, expired lease, provider timeout, duplicate request, cancel/retry, insufficient budget, and storage failure;
- company isolation, permission downgrade, signed URL expiry, malicious remote URL, and oversized upload;
- campaign pause/cancel and TikTok readiness.

Measure:

- time to validated project;
- time to first transcript/scene result;
- time to editable draft;
- final render real-time factor;
- provider failure/retry rate;
- cache hit rate and cost per finished minute;
- user edit rate and render-success rate.

## 15. Explicit Non-Goals For The First MVP

- Do not build a full nonlinear video editor.
- Do not support arbitrary animated caption templates before timing and persistence are reliable.
- Do not continuously render full-resolution video after every text edit.
- Do not index every campaign post into company RAG.
- Do not auto-approve unsupported business claims.
- Do not couple caption availability to one provider or one browser session.
